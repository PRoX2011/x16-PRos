# Контрибьютинг в x16-PRos

Спасибо за ваш интерес в контрибьютинге x16-PRos! Этот документ содержит различные туториалы по разработке програм и контрибьюции этой операционной системы.

---

## Стандарты кодинга

Весь код должен быть написан на **синтаксисе ассемблера NASM** и следовать следующим правилам:

### Правила именования

- **Определения**: Используйте строчные буквы и нижние подчеркивания
  ```nasm
  load_file:
  print_string:
  calculate_checksum:
  ```

- **Константы**: Используйте ЗАГЛАВНЫЕ символы с нижними подчеркиваниями
  ```nasm
  BUFFER_SIZE equ 512
  MAX_FILENAME_LENGTH equ 11
  VIDEO_MEMORY equ 0xB800
  ```

- **Переменные**: Используйте строчные символы и нижние подчеркивания
  ```nasm
  file_buffer: times 512 db 0
  current_position: dw 0
  error_flag: db 0
  ```

### Формат кода

- Используйте **4 пробела** для отступов внутри функций (без табуляции)
- Ставьте метки функций на 0 столбце (без отступов)
- Оставляйте пустые строки между определенияами для лучшей читаемости кода

**Пример:**

```nasm
print_hello:
    mov ah, 0x01
    mov si, hello_msg
    int 0x21
    ret
```

### Документация для функций

Для сложных определений, добавляйте хэдер используя этот формат:

```nasm
; ========================================================================
; FUNCTION_NAME - Brief description of what the function does
; IN:  AX = input parameter description
;      BX = another input parameter
; OUT: AX = return value description
;      CF = set on error, clear on success
;
; NOTE: Additional notes, warnings, or usage examples
; ========================================================================

function_name:
    ; Function implementation with 4-space indentation
    mov ax, bx
    ret
```

### Комментарии

- Используйте комментарии чтобы объяснить **почему** код делает что-то, не **что** он делает
- Сложные алгоритмы должны иметь пояснительные комментарии
- Пишите комментарии кратко и на Английском

**Хорошо:**
```nasm
; Convert LBA to CHS for BIOS compatibility
mov dx, ax
```

**Нехорошо:**
```nasm
; Move AX to DX
mov dx, ax
```

## Написание програм для x16-PRos

### Структура программы

**Минимальный пример `.BIN` программы:**

```nasm
[BITS 16]
[ORG 0x8000]

start:
    mov ah, 0x01
    mov si, hello_msg
    int 0x21
    ret

hello_msg db 'Hello, PRos!', 10, 13, 0
```

### Тестирование вашей программы

1. Положите ваш `.asm` файл в директорию `programs/` и обновите build скрипт
2. Пересоздайте образ диска: `./build-linux.sh`
3. Запустите в QEMU: `./run-linux.sh`
4. Внимательно протестируйте ваш функционал
5. Корректро отполируйте ошибки

### Создание Issue

При сообщении о багах или предложении новых функций:

1. Используйте **Английский** для всей коммуникации
2. Поищите существующие Issue для избежания дубликатов
3. Предоставляйте чистые, описательные заголовки
4. Включающие:
   - Шаги для воспроизведения (для поиска багов)
   - Ожидаемое и существующее поведение
   - Системную информацию (версия QEMU, и т.п.)
   - Скриншоты если нужно

**шаблон для Issue:**

```
**Description:**
Brief description of the bug or feature request

**Steps to Reproduce:** (for bugs)
1. Start the OS
2. Run command X
3. Observe error Y

**Expected Behavior:**
What should happen

**Actual Behavior:**
What actually happens

**Environment:**
- x16-PRos version: 0.5.9s
- Emulator: QEMU 8.0
```

### Создание Pull Requests

1. Форкните репозиторий
2. Создайте ветку для новой функции
3. Делайте изменения, используя стандарты кода
4. Корректно тестируйте в QEMU и также (при возможности) на реальной машине
5. Опубликуйте Commit с чистыми сообщениями
6. Откройте Pull Request с:
